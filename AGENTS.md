# Repository agent instructions

This repository is a hackathon prototype maintained by a five-person team. Work should be easy to review and keep `main` demo-ready.

## Working agreement

- Read `README.md` and `CONTRIBUTING.md` before making changes.
- Use a short-lived branch named `feat/`, `fix/`, `chore/`, `docs/`, or `design/` plus a kebab-case description. Do not commit directly to `main`.
- Open a pull request with a conventional title such as `feat: add signup flow` and use the PR template.
- Make the smallest coherent change, avoid unrelated refactors, and document assumptions when project requirements are undecided.
- Run relevant checks and report the exact commands or manual steps. Do not claim tests passed if they were not run.
- Never add secrets or personal data to the repository.
- Ask for human review before merging. Do not bypass branch protection.

## Project context

The stack and product scope are still being defined. Do not invent setup commands or architecture. Update the README when those decisions are made.
